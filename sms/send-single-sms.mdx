## Endpoint

<Badge color="blue">POST</Badge> `https://api.wapimax.com/sms/v1/send`

<Warning>
  Use `TextSMS` or `Texin` as your sender ID when sending SMS through WapiMax. We support additional sender IDs too. Visit **SMS** option in your dashboard sidebar to explore all available options.
</Warning>

## Authentication

Every request must include your API key in the `X-API-Key` header. See [Authorization](/get-started/authorization) to create one.

| Header | Value | Required |
| --- | --- | --- |
| `X-API-Key` | Your WapiMax API key | Yes |
| `Content-Type` | `application/json` | Yes |
| `Accept` | `application/json` | Recommended |

## Request body

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `to` | string | Yes | Recipient number in international format |
| `message` | string | Yes | Message text, max 5,000 characters |
| `sender_id` | string | Yes | Your registered, active sender ID |
| `schedule_at` | string | No | Future RFC3339 date-time with timezone |

  "request_id": "REQUEST_ID",

    "delivery_status": "pending",
    "sender_id": "TextSMS",
    "message_segments": 1,
    "charged": true
  }

</CodeGroup>

### Response fields

| Field | Type | Description |
| --- | --- | --- |
| `success` | boolean | Whether the request succeeded |
| `status` | integer | HTTP status code |
| `state` | string | Request state |
| `message` | string | Result message |
| `request_id` | string | Request ID for support |
| `data.message_id` | string | Message reference. Use it to check delivery |
| `data.to` | string | Recipient number |
| `data.send_status` | string | Submission state |
| `data.delivery_status` | string | Initial delivery state |
| `data.sender_id` | string | Sender ID used |
| `data.message_segments` | integer | Billable segments |
| `data.charged` | boolean | Whether the wallet was charged |
| `data.schedule_at` | string | Scheduled time, when set |

## Errors

| Status | Description |
| --- | --- |
| `400` | Invalid body, recipient, message, sender ID or schedule time |
| `401` | Missing or invalid API key |
| `402` | Insufficient SMS balance |
| `403` | Account inactive, no active plan or plan without SMS |
| `404` | Sender ID not found |
| `415` | `Content-Type` must be `application/json` |
| `422` | Recipient not supported by this sender ID |
| `429` | Too many failed requests. Retry after `Retry-After` seconds |
| `502` | Provider rejected the SMS or gave no conclusive response. Not charged |
| `503` | Service temporarily unavailable. Retry shortly |

## Notes

- Save `message_id` to check delivery with [Get delivery report](/sms/get-delivery-report).
- `accepted` means the provider accepted the SMS, not that it was delivered.
- One segment is 145 characters. Billing is per segment.
- Rejected messages are not charged.
- On `502`, check the message status before retrying.
- Include `request_id` when contacting support.
