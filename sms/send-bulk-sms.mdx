## Endpoint

<Badge color="blue">POST</Badge> `https://api.wapimax.com/sms/v1/send/bulk`

<Warning>
  Use `TextSMS` or `Texin` as your sender ID when sending SMS through WapiMax. We support additional sender IDs too. Visit **SMS** option in your dashboard sidebar to explore all available options.
</Warning>

## Authentication

Every request must include your API key in the `X-API-Key` header. See [Authorization](/get-started/authorization) to create one.

| Header | Value | Required |
| --- | --- | --- |
| `X-API-Key` | Your WapiMax API key | Yes |
| `Content-Type` | `application/json` | Yes |
| `Accept` | `application/json` | Recommended |

## Request body

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `recipients` | array | Yes | Recipient numbers in international format, 1 to 20 |
| `message` | string | Yes | Message text, max 5,000 characters |
| `sender_id` | string | Yes | Your registered, active sender ID |
| `schedule_at` | string | No | Future RFC3339 date-time with timezone. Applies to all recipients |

### Response fields

| Field | Type | Description |
| --- | --- | --- |
| `success` | boolean | Whether the request succeeded |
| `status` | integer | HTTP status code |
| `state` | string | `accepted`, `partial_success` or `failed` |
| `message` | string | Result message |
| `request_id` | string | Request ID for support |
| `data.total_count` | integer | Recipients in the request |
| `data.accepted_count` | integer | Messages accepted |
| `data.failed_count` | integer | Recipients that failed |
| `data.results` | array | Per-recipient results, in request order |

### Result fields

| Field | Type | Description |
| --- | --- | --- |
| `message_id` | string | Message reference, when processed |
| `to` | string | Recipient number |
| `status` | string | `accepted`, `failed` or `unknown` |
| `sender_id` | string | Sender ID used |
| `message_segments` | integer | Billable segments |
| `charged` | boolean | Whether the wallet was charged |
| `error` | string | Failure reason, when applicable |

## Errors

| Status | Description |
| --- | --- |
| `400` | Invalid body, recipients, message, sender ID or schedule time, or more than 20 recipients |
| `401` | Missing or invalid API key |
| `402` | Insufficient SMS balance |
| `403` | Account inactive, no active plan or plan without SMS |
| `404` | Sender ID not found |
| `415` | `Content-Type` must be `application/json` |
| `429` | Too many failed requests. Retry after `Retry-After` seconds |
| `502` | Provider rejected all recipients. Results are in the error body |
| `503` | Service temporarily unavailable. Retry shortly |

## Notes

- Check every item in `data.results`. A `200` can be `partial_success`.
- Unsupported recipients fail individually and are not charged. Others are still sent.
- A malformed number rejects the whole request.
- Save each `message_id` to check delivery with [Get delivery report](/sms/get-delivery-report).
- One segment is 145 characters. Billing is per segment.
